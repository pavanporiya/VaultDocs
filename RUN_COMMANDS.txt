============================================================================
 VAULTDOCS — LOCAL EXECUTION & OPERATIONS RUNBOOK
 Last Updated: 2026-10-23
============================================================================
 This runbook provides verified, step-by-step commands to configure,
 launch, test, and maintain the VaultDocs application locally. Follow
 each step in sequential order for initial setup or refer to the quick-start
 section for subsequent development sessions.

 PREREQUISITES (One-time installation):
   1. Python 3.11+          -> https://www.python.org/downloads/
   2. uv (Package Manager)  -> See installation instructions in STEP 1
   3. Node.js 18+ (LTS)     -> https://nodejs.org
   4. Docker Desktop        -> https://www.docker.com/products/docker-desktop
                               (Recommended method for database provisioning)

 Environment Verification (PowerShell / Terminal):
   python --version
   node --version
   npm --version
   docker --version

============================================================================
 STEP 0 — CLONE OR LOCATE REPOSITORY
============================================================================

 For a new installation (fresh clone):

     git clone https://github.com/pavanporiya/VaultDocs.git
     cd VaultDocs

 If the repository is already present, navigate to the project root:

     cd path/to/VaultDocs

============================================================================
 STEP 1 — INSTALL uv PACKAGE MANAGER (If not already installed)
============================================================================

 Windows (PowerShell):

     powershell -c "irm https://astral.sh/uv/install.ps1 | iex"

 macOS / Linux:

     curl -LsSf https://astral.sh/uv/install.sh | sh

 Verify installation:

     uv --version

 NOTE: You may need to restart your terminal session after installation
 for the `uv` executable to be recognized in your system PATH.

============================================================================
 STEP 2 — PROVISION DATABASE (PostgreSQL)
============================================================================

 OPTION A (RECOMMENDED): Standalone Docker Container with Persistent Volume

     docker run -d --name vaultdocs-db -v vaultdocs-db-data:/var/lib/postgresql/data -e POSTGRES_DB=VaultDocs -e POSTGRES_USER=VaultDocs_user -e POSTGRES_PASSWORD=change-me-in-production -p 5433:5432 --restart unless-stopped postgres:16-alpine

 NOTE: The `-v vaultdocs-db-data:/var/lib/postgresql/data` parameter uses a
 named Docker volume. Your database contents remain fully persistent and safe
 across container stops, restarts, or image rebuilds.

 To stop the database container (data remains intact):

     docker stop vaultdocs-db

 To restart the database container:

     docker start vaultdocs-db

 OPTION B: Docker Compose (Database service only from repo root):

     docker compose up -d db

 OPTION C: Local PostgreSQL Installation:
     - Ensure PostgreSQL service is active.
     - Create a database named "VaultDocs".
     - Update `.env` credentials accordingly (refer to STEP 3).

============================================================================
 STEP 3 — CONFIGURE ENVIRONMENT VARIABLES (.env)
============================================================================

 Create a `.env` file in the project root directory with the following configuration:

     # --- Database Configuration ---
     DATABASE_HOST=localhost
     DATABASE_PORT=5433
     DATABASE_NAME=VaultDocs
     DATABASE_USER=VaultDocs_user
     DATABASE_PASSWORD=change-me-in-production

     # --- Application Configuration ---
     APP_ENV=development
     DEBUG=true
     SECRET_KEY=change-this-to-any-random-secret-string

 NOTES:
   - Never commit `.env` into version control. It is ignored by default.
   - The credentials above match the STEP 2 Option A Docker container settings
     and work immediately without modifications.

============================================================================
 STEP 4 — BACKEND DEPENDENCY INSTALLATION
============================================================================

 From the repository root directory:

     uv sync

 This installs all required Python packages and automatically provisions
 an isolated virtual environment (`.venv`).

============================================================================
 STEP 5 — APPLY DATABASE MIGRATIONS
============================================================================

 From the repository root directory:

     uv run alembic upgrade head

 NOTE: This operation is idempotent. It applies all pending schema changes
 safely without reapplying previously executed migrations.

============================================================================
 STEP 6 — START BACKEND SERVER
============================================================================

 From the repository root directory:

     uv run uvicorn vaultdocs.main:app --port 8000

 Verify the backend status in a separate terminal:

     curl http://localhost:8000/v1/health

 Expected response:
     {"status":"healthy","database":"connected",...}

 Interactive API Documentation (Swagger UI):
     http://localhost:8000/docs

============================================================================
 STEP 7 — START FRONTEND APPLICATION (Open a new terminal)
============================================================================

 Navigate to the frontend directory and start the Vite dev server:

     cd frontend
     npm install
     npm run dev

 The Vite development server will display the local address, typically:

     Local: http://localhost:3000/

 Open this URL in your web browser. You can now register an account,
 authenticate, and interact with the application.

 NOTES:
   - If port 3000 is occupied, Vite will automatically select 3001 or 3002.
     Always use the port displayed in your terminal.
   - The Vite development server automatically proxies `/v1` API requests to
     the FastAPI backend at `http://localhost:8000`. No extra proxy setup is needed.

============================================================================
 DAILY DEVELOPMENT QUICK-START (Subsequent Sessions)
============================================================================

 Terminal 1 (Database — if not currently running):
     docker start vaultdocs-db

 Terminal 2 (Backend API):
     uv run uvicorn vaultdocs.main:app --port 8000

 Terminal 3 (Frontend Client):
     cd frontend && npm run dev

 Application URL:
     http://localhost:3000

============================================================================
 TROUBLESHOOTING & COMMON ISSUES
============================================================================

 1) Error: "relation users does not exist" or HTTP 500 on registration
    Cause: Database migrations have not been applied yet.
    Resolution: Run the migration command from the project root:
        uv run alembic upgrade head

 2) Port 8000 already in use (WinError 10048 / EADDRINUSE)
    Cause: A previous backend instance or orphaned process is holding port 8000.
    Resolution: Terminate the blocking process:
        Windows (PowerShell/CMD):
            netstat -ano | findstr :8000
            taskkill /PID <PID_NUMBER> /F
        macOS / Linux:
            kill $(lsof -t -i:8000)

 3) Database connection refused or "database": "disconnected" in health check
    Cause: The PostgreSQL container is stopped or connection details do not match.
    Resolution:
        - Check container status:
            docker ps
        - If the container is stopped, start it:
            docker start vaultdocs-db
        - Ensure `.env` parameters (port 5433, user, password) match your container.

 4) Frontend API or Network errors (CORS / Proxy failures)
    Cause: Backend server is offline or not responding on port 8000.
    Resolution:
        - Verify backend health:
            curl http://localhost:8000/v1/health
        - Restart the backend server if necessary.

 5) Registration or Login returns "invalid email"
    Cause: The validation rules disallow non-standard or reserved testing domains
           (such as `.test` or `.local`).
    Resolution: Use standard email addresses (e.g., user@example.com).

 6) `npm install` failures or dependency conflicts
    Cause: Incompatible Node version or stale cache/lockfiles.
    Resolution:
        - Verify Node.js version (18+ required):
            node --version
        - Perform a clean dependency reset:
            cd frontend
            # Windows:
            rmdir /s /q node_modules
            del package-lock.json
            # macOS / Linux:
            rm -rf node_modules package-lock.json
            # Reinstall:
            npm install

 7) Command not recognized: "uv: command not found"
    Cause: Terminal PATH environment has not updated after installation.
    Resolution: Restart your terminal session or repeat STEP 1.

 8) Document upload rejected or failing
    Cause: File size exceeds the backend upload ceiling.
    Resolution: The maximum allowed file size is 10 MB. Test with smaller payloads.

============================================================================
 OPTIONAL — FULL DOCKER COMPOSE MODE (Containerized Backend + Database)
============================================================================

 To launch the complete stack (backend and database) using Docker Compose:

     docker compose up -d --build
     uv run alembic upgrade head
     cd frontend && npm run dev

 View backend application logs:
     docker compose logs -f app

 Stop the containerized stack safely (data volume is preserved):
     docker compose down

 CRITICAL WARNING — DO NOT EXECUTE THE FOLLOWING COMMAND:
     # docker compose down -v   <-- DANGER: Drops persistent database volumes.

============================================================================
 CODE QUALITY, TESTING & AUTOMATION (For Developers)
============================================================================

 Backend Quality Checks & Test Suite (From project root):

      uv run pytest
      uv run ruff check .
      uv run ruff format --check .
      uv run mypy backend/src
      uv run alembic check

 TEST ISOLATION & DATA SAFETY GUARANTEE:
   `uv run pytest` automatically connects exclusively to the isolated test
   database `VaultDocs_test`. The test suite will immediately abort with a
   runtime safety error if it ever attempts to target the primary `VaultDocs`
   development database. Your live development data remains 100% protected.

 Database Backup & Restore Operations:

   Create manual snapshot (timestamped custom format `.dump` in `backups/`):
       powershell -File scripts/backup_postgres.ps1

   Safely restore a snapshot into a target database:
       powershell -File scripts/restore_postgres.ps1 -DumpFile "backups\<filename>.dump" -TargetDatabase "VaultDocs_restore_test"

 Frontend Linting & Production Build:

     cd frontend
     npm run lint
     npm run build

 Full End-to-End Test Suite (Ensure backend on :8000 and frontend on :3000 are running):

     node scripts/e2e-api-verify.mjs
     node scripts/e2e-browser-qa.mjs http://localhost:3000
